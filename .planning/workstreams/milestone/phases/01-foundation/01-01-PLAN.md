<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer laptop -> PostgreSQL | `DATABASE_URL` crosses from env/config into the driver adapter; leakage would expose DB credentials |
| npm registry -> node_modules | Prisma 7 + @prisma/adapter-pg + pg binaries enter the runtime; compromised packages would have DB access |
| Prisma CLI -> filesystem | `prisma generate` writes to `src/generated/prisma` and `prisma migrate` writes migration SQL to `prisma/migrations` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01-01 | Information Disclosure | `DATABASE_URL` in logs/errors | mitigate | `PrismaService` constructor reads from `process.env.DATABASE_URL` only; never interpolate the URL into error messages. `.env` is gitignored (existing rule at .gitignore line 39). `.env.example` ships placeholder only. Prisma 7's default error formatting does not leak the connection string. |
| T-01-01-02 | Information Disclosure | Committed `prisma.config.ts` | mitigate | `prisma.config.ts` uses `env('DATABASE_URL')` helper — it reads at runtime, the literal URL is never in the committed file. Verified by the file containing the string `env('DATABASE_URL')` and NO `postgresql://` literal. |
| T-01-01-03 | Tampering | Generated Prisma client committed to git | mitigate | `.gitignore` appended with `/src/generated` rule; `postinstall: prisma generate` script ensures fresh clones regenerate on `npm install`. Verified by `grep /src/generated .gitignore` returning a match. |
| T-01-01-04 | Denial of Service | Prisma connection exhausts DB pool | accept | Phase 1 uses default `pg.Pool` settings from `@prisma/adapter-pg`. Pool tuning is a production concern deferred until traffic exists; NO known DoS vector in a single-developer dev environment. |
| T-01-01-05 | Elevation of Privilege | Destructive migration applied to prod | mitigate | Phase 1 uses `prisma migrate dev` (dev only — creates migration files). `prisma migrate deploy` (production command) is NOT added to any script. RESEARCH.md anti-pattern note documents this explicitly. |
| T-01-01-06 | Tampering | Soft delete bypass in queries | accept | Phase 1 intentionally does not implement global `$extends` soft-delete filtering (RESEARCH.md Pitfall 8). Direct queries in Phases 2–5 must manually include `where: { deletedAt: null }` where applicable. Automatic filtering is a Phase 6 concern (Event CRUD). Documented to Phase 6. |
| T-01-01-07 | Information Disclosure | `pg` driver raw SQL errors bubble to HTTP | accept | No HTTP endpoints added in this plan. Plan 01-02 installs `ValidationPipe`; raw Prisma errors will be covered by the default NestJS exception filter (D-09). Phase-level concern tracked in Plan 01-02 threat model. |
</threat_model>
