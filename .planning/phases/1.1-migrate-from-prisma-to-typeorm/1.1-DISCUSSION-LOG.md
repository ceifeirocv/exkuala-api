## Entity Definition Style

| Option | Description | Selected |
|--------|-------------|----------|
| Decorator-based | @Entity()/@Column() decorators on plain TS classes — NestJS/TypeORM standard | ✓ |
| Schema-first / no decorators | Plain classes, manage schema via raw SQL migrations only — honours original CLAUDE.md rule | |

**User's choice:** Decorator-based (Recommended)
**Notes:** Supersedes the prior CLAUDE.md "no TypeORM decorators" rule which predated this migration phase.

## Migration Strategy

### Migration history handling

| Option | Description | Selected |
|--------|-------------|----------|
| Single baseline migration | Squash everything into one TypeORM migration from current schema | ✓ |
| Keep Prisma migrations, add TypeORM on top | Leave prisma/migrations/ in place, generate TypeORM diff migration | |
| synchronize: true in dev only | Auto-apply schema from entities in dev; migrations only for prod | |

**User's choice:** Single baseline migration

### synchronize in development

| Option | Description | Selected |
|--------|-------------|----------|
| Always explicit migrations | synchronize: false everywhere | |
| synchronize: true in dev | Allow in development for fast loop, disabled in staging/prod | ✓ |

**User's choice:** synchronize: true in dev (Recommended)

## Repository Injection Pattern

| Option | Description | Selected |
|--------|-------------|----------|
| TypeOrmModule.forFeature + @InjectRepository | Per-module entity registration + @InjectRepository() in services | ✓ |
| DataSource injection | Inject DataSource directly, call dataSource.getRepository() | |

**User's choice:** TypeOrmModule.forFeature + @InjectRepository (Recommended)

---

## TypeORM Data Source Config

| Option | Description | Selected |
|--------|-------------|----------|
| forRootAsync + separate data-source.ts | AppModule uses forRootAsync with ConfigService; separate data-source.ts for CLI | ✓ |
| Single ormconfig object | One shared ormconfig.ts for both AppModule and CLI | |

**User's choice:** forRootAsync + separate data-source.ts (Recommended)
