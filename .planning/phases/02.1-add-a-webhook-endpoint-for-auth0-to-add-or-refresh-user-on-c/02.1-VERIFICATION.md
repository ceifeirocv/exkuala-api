> **Note on SC-2 (401 vs 403):** The success criterion states "without secret returns 401". NestJS translates a guard returning `false` to a `ForbiddenException` (403), not `UnauthorizedException` (401), unless the guard explicitly throws. The current implementation returns `false`, which yields 403 in production. The spec suite does not test the HTTP status code (only `canActivate` return value), so this nuance is not caught by tests. This is a minor deviation from the success criterion wording but does not affect security correctness — the request is rejected. Flagging as a WARNING, not a BLOCKER, because the guard behavior (reject unauthenticated requests) is functionally correct.
