## Decisions Made

- Pre-generate cuid2 `id` in `upsertFromAuth0()` rather than relying on `@BeforeInsert` — TypeORM's `repository.upsert()` bypasses all entity lifecycle hooks. The entity comment documents this constraint with a reference to RESEARCH.md Pitfall 1.
- Two-entry `transformIgnorePatterns`: first entry handles pnpm's `.pnpm/<pkg+version>/node_modules/<pkg>` path structure; second entry handles direct `node_modules/<pkg>` paths. Both entries exclude ESM-only packages (cuid2, @noble/hashes, @noble/ciphers, jwks-rsa, jose) from the ignore list so ts-jest transforms them.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Fixed pnpm ESM transform for @paralleldrive/cuid2**
- **Found during:** Task 2 (Create UsersService and UsersModule)
- **Issue:** Jest `transformIgnorePatterns` had a single pattern `/node_modules/(?!(cuid2|...))` that matched the first `/node_modules/` segment in pnpm's nested path `.pnpm/@paralleldrive+cuid2@3.3.0/node_modules/...`. Since the text after that match was `.pnpm/...` (not a package name), the negative lookahead passed, causing cuid2 to be treated as a CommonJS-ignoreable module. ts-jest never transformed it, yielding `SyntaxError: Cannot use import statement outside a module`.
- **Fix:** Replaced single pattern with two entries: a pnpm-aware pattern that matches `.pnpm/<pkg>/node_modules/<excluded-pkg>` and a direct-layout pattern that excludes `.pnpm` from matching via `(?!\\.pnpm|...)`.
- **Files modified:** `package.json`
- **Verification:** `node -e` regex tests confirm cuid2 pnpm path is not ignored; `pnpm test --testPathPatterns=users.service` exits 0 (3 tests pass).
- **Committed in:** `9545bfc` (Task 2 commit)
