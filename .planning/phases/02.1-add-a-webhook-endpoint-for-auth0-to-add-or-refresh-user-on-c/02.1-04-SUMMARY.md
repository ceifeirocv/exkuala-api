## Decisions Made

- `@Public()` placed before `@UseGuards(WebhookSecretGuard)` — order of decorators is bottom-up at runtime; APP_GUARDs evaluate @Public() metadata first and short-circuit, then WebhookSecretGuard runs for actual header validation
- WebhooksModule has no APP_GUARD providers — JwtAuthGuard and RolesGuard are already APP_GUARD in AuthModule; re-registering would double-execute on every route
