  <what-built>
    Phase 7 Public Event Discovery:
    - GET /api/v1/events — unauthenticated public event listing with cursor pagination
    - GET /api/v1/events/:id — unauthenticated public event detail
    - PUT /api/v1/organizer/events/:id/translations/:locale — organizer translation upsert
    - EventTranslationEntity with composite PK and CASCADE FK
    - tsvector full-text search on events.title + events.description + all translations content
    - GIN index on search_vector for fast full-text queries
    - City LIKE prefix filter (DISC-03)
    - Category slug filter (DISC-01)
    - Date range filter (DISC-02)
    - Translations map in response: { pt: { title, description }, en: { ... } } (D-01)
  </what-built>
  <how-to-verify>
    **Prerequisites:** Ensure at least one PUBLISHED event exists in the database. If none exist, create one via `POST /api/v1/organizer/events` with a valid organizer JWT and then publish it via `PATCH /api/v1/organizer/events/:id` with `{ "status": "published" }`.

    **Criterion 1: Unauthenticated public listing returns only published events (EVT-04, EVT-06)**
    ```bash
    curl -s http://localhost:3000/api/v1/events | jq '{ hasMore, count: (.data | length), statuses: [.data[].status] | unique }'
    ```
    Expected: `{ hasMore: false|true, count: N, statuses: ["PUBLISHED"] }` — only PUBLISHED events, never DRAFT or CANCELLED.

    **Criterion 2: Category, date, and city filters scope results (DISC-01, DISC-02, DISC-03)**
    ```bash
    # Category filter (use a real slug from your DB)
    curl -s "http://localhost:3000/api/v1/events?category=music" | jq '.data | length'

    # City filter (use a city from an existing event)
    curl -s "http://localhost:3000/api/v1/events?city=Praia" | jq '[.data[].city] | unique'

    # Date range filter
    curl -s "http://localhost:3000/api/v1/events?start=2026-01-01&end=2026-12-31" | jq '.data | length'
    ```
    Expected: results scoped to filter values.

    **Criterion 3: Full-text search via ?q= returns relevant results (DISC-04)**
    First, ensure a published event's title contains a word you can search. Then:
    ```bash
    # Insert a published event with title 'Jazz Night' if needed, or use an existing word
    curl -s "http://localhost:3000/api/v1/events?q=jazz" | jq '[.data[].title]'
    ```
    Expected: only events whose title or description contains 'jazz' (via tsvector).

    **Criterion 4: Translations map returned, all locales present (I18N-01, I18N-03)**
    First upsert a translation via organizer endpoint (replace <JWT>, <EVENT_ID>):
    ```bash
    curl -s -X PUT \
      -H "Authorization: Bearer <JWT>" \
      -H "Content-Type: application/json" \
      -d '{"title": "Noite de Jazz", "description": "Uma noite especial."}' \
      "http://localhost:3000/api/v1/organizer/events/<EVENT_ID>/translations/pt" | jq .
    ```
    Expected: `{ "locale": "pt", "title": "Noite de Jazz", "description": "Uma noite especial." }`

    Then retrieve the event:
    ```bash
    curl -s "http://localhost:3000/api/v1/events" | jq '.data[0].translations'
    ```
    Expected: `{ "pt": { "title": "Noite de Jazz", "description": "Uma noite especial." } }`

    Also verify tsvector updated (translation content searchable):
    ```bash
    curl -s "http://localhost:3000/api/v1/events?q=especial" | jq '[.data[].id]'
    ```
    Expected: event with Portuguese translation appears in results.

    **Criterion 5: GET /api/v1/events/:id returns full detail without auth (EVT-04)**
    ```bash
    curl -s "http://localhost:3000/api/v1/events/<EVENT_ID>" | jq '{ id: .id, status: .status, organizer: .organizer, ticketPrice: .ticketPrice }'
    ```
    Expected: 200 response with id, status=PUBLISHED, full organizer shape (id, name, bio, contact), ticketPrice present (even if null).

    **Swagger docs check:**
    Visit http://localhost:3000/api/docs and confirm:
    - GET /events and GET /events/{id} appear under "Events" tag (not under "Organizer Events")
    - PUT /organizer/events/{id}/translations/{locale} appears under "Organizer Events" tag
  </how-to-verify>
