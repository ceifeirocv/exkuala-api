  <how-to-verify>
    You need an approved organizer JWT. If Phase 5 is complete you already have one. If not, create an organizer via POST /api/v1/organizers and approve via the admin endpoint.

    **Test 1 — Create a draft event:**
    ```bash
    curl -s -X POST http://localhost:3000/api/v1/organizer/events \
      -H "Authorization: Bearer $ORGANIZER_JWT" \
      -H "Content-Type: application/json" \
      -d '{"title": "Test Jazz Night", "startAt": "2027-06-01T20:00:00.000Z", "categoryId": "<valid-category-id>"}' \
      | jq '.'
    ```
    Expected: 201 response with id, status="DRAFT", organizerId set to your organizer ID.

    Save the returned event ID as EVENT_ID.

    **Test 2 — Try to publish without required fields (should fail 422):**
    ```bash
    curl -s -X PATCH http://localhost:3000/api/v1/organizer/events/$EVENT_ID \
      -H "Authorization: Bearer $ORGANIZER_JWT" \
      -H "Content-Type: application/json" \
      -d '{"status": "PUBLISHED"}' \
      | jq '.'
    ```
    Expected: 422 with `{ missing: ["description", "venueName", "address"] }` (or similar).

    **Test 3 — Fill required fields and publish (should succeed):**
    ```bash
    curl -s -X PATCH http://localhost:3000/api/v1/organizer/events/$EVENT_ID \
      -H "Authorization: Bearer $ORGANIZER_JWT" \
      -H "Content-Type: application/json" \
      -d '{"description": "A night of jazz classics", "venueName": "Casa da Música", "address": "Av. da Boavista 604, Porto", "status": "PUBLISHED"}' \
      | jq '.'
    ```
    Expected: 200 with status="PUBLISHED".

    **Test 4 — Cancel the published event:**
    ```bash
    curl -s -X PATCH http://localhost:3000/api/v1/organizer/events/$EVENT_ID \
      -H "Authorization: Bearer $ORGANIZER_JWT" \
      -H "Content-Type: application/json" \
      -d '{"status": "CANCELLED"}' \
      | jq '.'
    ```
    Expected: 200 with status="CANCELLED".

    **Test 5 — Try to delete a non-draft event (should fail 409):**
    ```bash
    curl -s -X DELETE http://localhost:3000/api/v1/organizer/events/$EVENT_ID \
      -H "Authorization: Bearer $ORGANIZER_JWT" \
      | jq '.'
    ```
    Expected: 409 with message mentioning "only draft events are deletable".

    **Test 6 — Create a second draft and soft-delete it:**
    ```bash
    curl -s -X POST http://localhost:3000/api/v1/organizer/events \
      -H "Authorization: Bearer $ORGANIZER_JWT" \
      -H "Content-Type: application/json" \
      -d '{"title": "Test Event to Delete", "startAt": "2027-07-01T20:00:00.000Z", "categoryId": "<valid-category-id>"}' | jq '.id'

    # Use the returned ID as DRAFT_ID
    curl -s -X DELETE http://localhost:3000/api/v1/organizer/events/$DRAFT_ID \
      -H "Authorization: Bearer $ORGANIZER_JWT" \
      -w "\nHTTP %{http_code}"
    ```
    Expected: HTTP 204 (no body). Row still exists in DB with deletedAt set — soft delete confirmed by checking it no longer appears in GET list.

    **Test 7 — GET own events list:**
    ```bash
    curl -s http://localhost:3000/api/v1/organizer/events \
      -H "Authorization: Bearer $ORGANIZER_JWT" \
      | jq '{ hasMore, nextCursor, count: (.data | length) }'
    ```
    Expected: `{ data: [...], hasMore: false, nextCursor: null }`. Soft-deleted event does NOT appear.

    **Test 8 — Cross-organizer ownership (needs a second organizer JWT):**
    If you have a second approved organizer JWT ($ORGANIZER_JWT_2):

    ```bash
      | jq '.statusCode'
    ```
    Expected: 404 (no 403 — ownership leakage prevention per D-21).
