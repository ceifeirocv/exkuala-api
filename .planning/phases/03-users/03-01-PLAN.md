The decorator uses `createParamDecorator` — the factory callback is the testable unit. NestJS exposes the inner callback via the decorator's second argument when called directly. The standard test pattern is to invoke the factory function that `createParamDecorator` receives, not the decorator itself.

However, since `createParamDecorator` is a NestJS internal, the cleanest unit test approach is to mock `ExecutionContext` and call the decorator's underlying factory directly. To do this without importing the not-yet-created decorator file, write the spec to import `CurrentUser` and use a helper that extracts the callback:

```typescript

describe('@CurrentUser() decorator', () => {
  it('returns req.user typed as AuthenticatedUser from the HTTP context', () => {
    const fakeUser: AuthenticatedUser = {
      id: 'usr_01',
      auth0Id: 'auth0|test123',
      createdAt: new Date('2024-01-01'),
      updatedAt: new Date('2024-01-01'),
      roles: ['user'],
```

```typescript
    const fakeUser: AuthenticatedUser = {
      id: 'usr_01',
      auth0Id: 'auth0|test123',
      createdAt: new Date('2024-01-01'),
      updatedAt: new Date('2024-01-01'),
      roles: ['user'],
```

```typescript
    const mockRequest = { user: fakeUser };
    const mockHttp = { getRequest: () => mockRequest };

      switchToHttp: () => mockHttp,

    // Simplest approach: call the factory via the internal __paramDecoratorFactory symbol

      const result = paramFactory(undefined, mockContext);
```
